## 2. Matriz de Remediaciones Implementadas (F01 - F08)

### F02 (P2) - Reversión limpia y aislamiento de caché Apollo en CvEditorProfile.tsx
* **Defecto previo:** Callback `update` escribía `nextPrivacy` optimistamente antes del control `response.data?.toggleProfilePrivacy?.success`.
* **Solución aplicada:**
  1. Se eliminó la escritura optimista en `update`.
  2. La caché de Apollo (`GET_USER_PROFILE`) se actualiza por escritura controlada únicamente tras verificar `success === true`.
  3. En caso de fallo de red o `success === false`, se lanza excepción, se revierte el estado local (`isPublicProfile: !nextPrivacy`), se activa `setSaveStatus('error')` desplegando mensaje al usuario, y la caché de Apollo permanece inalterada con el valor real anterior.
  4. El botón de switch se desactiva durante la mutación con `disabled={savingPrivacy || savingProfile}`.
* **Pruebas añadidas en `CvEditorProfile.lifecycle.test.tsx` (11/11 PASS):**
  * `updates Apollo cache only when toggleProfilePrivacy succeeds`
  * `does not update Apollo cache and reverts state when toggleProfilePrivacy returns failure`

### F03 (P2) - Apertura de hilos en Feed por clave compuesta targetInquiryId + targetCommentId
* **Defecto previo:** `autoOpenedInquiryRef.current` guardaba sólo `targetInquiryId`, impidiendo abrir otro comentario del mismo post si el usuario lo había replegado.
* **Solución aplicada:**
  1. Se actualizó la guardia a clave compuesta: `targetKey = `${targetInquiryId}:${targetCommentId || ''}``.
  2. Navegar hacia un comentario diferente del mismo post genera un `targetKey` distinto y reabre el hilo (`openThreads[targetInquiryId] = true`).
  3. Al refetchear el feed o mutar sin cambiar el destino, la clave coincide con el ref, preservando el repliegue manual del usuario.
* **Prueba añadida en `Feed.interactions.test.jsx` (5/5 PASS):**
  * `re-opens thread when targetCommentId changes on the same inquiryId and preserves closed state on same key`

### F04 (P1) - Formalización de Decisión de Alcance: Moderador vs. Administrador
