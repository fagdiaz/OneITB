# Speckit Debugger & Runtime Reconciliation Skill

This skill is designed for high-reasoning debugger agents (e.g. Claude Sonnet Thinking) to diagnose and fix real runtime errors in OneITB23 that static audits or unit test mocks fail to catch.

## Core Protocols

### Protocol 1: Runtime Error Interception & UUID Decoding
When the UI displays `Código: <UUID>`:
1. It is generated by `createInterfaceErrorId()` in `InterfaceFailureView.tsx` when `GlobalErrorBoundary.tsx` catches an unhandled React error.
2. The real stack trace is logged in the Vite runtime log (`.system_generated/tasks/task-*.log` running `npm run dev`) with `[Unhandled error]` or `Unhandled OneITB interface error`.
3. Check for:
   - `ReferenceError`: Variables used in JSX but not declared or destructured from hooks.
   - Apollo `skip` query violations: calling `refetch()` on a query that was skipped.
   - Undefined prop accesses or broken imports.

### Protocol 2: Reference Implementation Reconciliation (`F:\React\cv-builder`)
When restoring or verifying the CV Builder & ATS Print Engine:
1. `F:\React\cv-builder` is the canonical Ground Truth for CV preview and print formatting.
2. Inspect:
   - `F:\React\cv-builder\src\index.css`: Check `@page { size: A4; margin: 12mm; }`, `.resume-print-target`, `.resume-theme-*`, and layout utilities.
   - `F:\React\cv-builder\src\components\resume\ResumePreview.tsx`: Check A4 scale formulas, CSS pixel/mm ratios, section dividers, and print classes.
3. Integrate only what OneITB needs: clean A4 ATS print styling, theme classes, and proper page flow into `FrontEnd/OneItb-FE/src/index.css` and `CVATSPrintTemplate.tsx`.

### Protocol 3: Realtime Concurrency & WebSocket Subscriptions
1. WebSocket status transitions (`connected`, `disconnected`, `error`) must always wrap `refetch()` calls in safe `.catch()` handlers.
2. Subscription consumers must always destructure both `socketStatus` and `subscriptionError`.
3. Ensure unmount cleanup (`mountedRef.current = false`) in all hooks.
