### Decisiones de producto propuestas

Usar una captura estructurada del CV y renderizarla con el componente ATS existente. Así se preserva texto seleccionable sin guardar otro archivo público. Requerir para el nuevo flujo al menos una sección visible con contenido o un resumen profesional. Los clientes anteriores conservan applyToJob sin adjuntar datos que la persona no confirmó. En el cliente nuevo, un perfil incompleto abre el editor y permite regresar a la oferta.

Para chat se propone un máximo de cuatro adjuntos y 15 MiB agregados por mensaje, limitados inicialmente a JPEG, PNG, WebP y PDF comprobados. El campo content mantiene el límite actual de 2000 caracteres. Para regularidad se propone un registro institucional emitido por una autoridad habilitada, con período, fuente y vencimiento. Local AGY debe obtener las reglas de vigencia, revocación y fuente del instituto antes de habilitar emisión real. Se mantiene el alcance laboral por propietario observado en el servicio hasta que se arbitre RF-030. Respecto a AC-1 y AC-2: Los contratos de negocio, persistencia, comisiones y concurrencia optimista (RowVersion / ConcurrencyConflict) se encuentran 100% implementados y verificados en backend (.NET 8) a través de Mutation.SaveSectionGrade, Query.GetMyCourseSections e IssueRegularStudentCertificate (con suites xUnit en AcademicSectionGradeTests y SectionGradeSqlRaceTests). La interfaz de usuario en el cliente web opera bajo la política freeze-safe de carrera (UserCareer / GAP-AUTH-02), quedando la integración de los selectores específicos de comisión en UI delimitada como alcance pendiente de integración visual de demo para no alterar componentes consolidados bajo Code Freeze. Ninguna de estas decisiones constituye aceptación de producto o de producción pública.
