# Data Model: QA Session 2 Social Core Fixes

## SocialAttachment

| Field | Type | Rules |
|---|---|---|
| Id | Guid | PK, generated by application |
| InquiryId | Guid? | FK restrictive; XOR with CommentId |
| CommentId | Guid? | FK restrictive; XOR with InquiryId |
| FileUrl | string | required, max 500, `/uploads/` or approved Cloudinary HTTPS |
| OriginalFileName | string | required, sanitized basename, max 255 |
| ContentType | string | required, allowlisted, max 100 |
| Size | long | 1..15 MB for new uploads; 0 allowed only for migrated legacy data |
| SortOrder | int | 0..9 unique per owner by application validation |
| CreatedAt | DateTime | UTC |

Relationships: `Inquiry 1:N SocialAttachment`, `Comment 1:N SocialAttachment`, all deletes restrictive. Check constraint enforces exactly one owner. Indices on `(InquiryId, SortOrder)` and `(CommentId, SortOrder)`.

## CommentReaction

| Field | Type | Rules |
|---|---|---|
| Id | Guid | PK |
| CommentId | Guid | FK restrictive |
| UserId | Guid | FK restrictive |
| CreatedAt | DateTime | UTC |

Unique index `(CommentId, UserId)`. Query filter excludes reactions whose comment or inquiry is inactive.

## Notification extensions

| Field | Type | Rules |
|---|---|---|
| GroupKey | string? | max 160; unique with UserId when not null |
| AggregateCount | int | default 1, minimum 1 |
| RelatedInquiryId | Guid? | FK restrictive |
| UpdatedAt | DateTime? | latest grouped event UTC |
| RowVersion | byte[] | SQL rowversion concurrency token |

`SocialReaction` is added to `NotificationType`. Existing records receive `AggregateCount=1`; non-grouped notifications keep `GroupKey=null`.

## Compatibility migration

1. Create `SocialAttachments` and `CommentReactions`.
2. Add nullable grouping fields/default counter to `Notifications`.
3. Backfill every non-null `Inquiry.FileUrl` and `Comment.FileUrl` into `SocialAttachments` with derived physical filename, `application/octet-stream`, size 0 and order 0.
4. Keep legacy columns and populate them with the first attachment for new writes.
5. Add constraints/indices only after backfill.
